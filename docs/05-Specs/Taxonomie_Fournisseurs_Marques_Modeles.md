## 3. Mapping Marques → Familles

Chaque marque est liée à une ou plusieurs familles d'équipement via la table `brand_family_mapping`.

| Famille | Marques associées |
|---------|-------------------|
| **Audiovisuel** | Barco, Blackmagic Design, Christie, Extron, Hollyland, LG, MuxLab, Novastar, Panasonic, Samsung, Sony, Unilumin |
| **Backline** | DW, Fender, Marshall, Pearl, Sabian |
| **Divers** | Klotz, Neutrik, Procab, Sommer |
| **Sonorisation** | APG, Adamson, Allen & Heath, Alto, Apart, Audinate, Audio-Technica, BSS, Behringer, DBX, DPA, Denon, Drawmer, Ecler, Empirical Labs, Focusrite, Fohhn, HK Audio, Klark Teknik, L-Acoustics, Lab Gruppen, Lexicon, Mackie, Midas, Neve, Nexo, QSC, Radial, SPL, Sennheiser, Shure, Tube-Tech, Universal Audio, Yamaha |
| **Structure** | ASD, CM, Chainmaster, Doughty, Europodium, Layher, Liftket, Manfrotto, Prolyte, Stacco, Stagedex, Stagemaker, VMB, Work Pro |
| **Éclairage** | Avolites, Ayrton, Cameo, Chauvet, Clay Paky, DAP Audio, ETC, GLP, Juliat, MA Lighting, Martin, Nicols, Prolights, RVE, Robe, Robert Juliat, Showtec, Starway |

### Règles métier
1. **1 marque = 1 famille primaire** : Chaque marque a un `primary_domain` qui détermine sa famille principale.
2. **Câbles → Divers** : Neutrik, Sommer, Procab, Klotz sont transversaux (audio, vidéo, éclairage) ; ils sont mappés à Divers.
3. **Détection automatique** : Le backend (`brandHelpers.js`) normalise les textes bruts vers la marque canonique via un cache LRU avec TTL de 60 secondes.
4. **brand_id** : Clé étrangère dans `equipment` et `supplier_articles` pointant vers `brands.id`.
5. **brand_canonical** : Nom affiché de la marque canonique, résolu par JOIN sur `brands`.

## 4. Alias et normalisation

### Table `brand_aliases` (64 entrées)

Les alias permettent de résoudre les variantes de saisie vers la marque canonique :

| Catégorie d'alias | Exemples | Nombre |
|-------------------|----------|--------|
| MAJUSCULES → Canonique | SHURE → Shure, YAMAHA → Yamaha | 54 |
| Typos courantes | NEUTRICK → Neutrik, LFTKET → Liftket | 2 |
| Abréviations | BLACKMAGIC → Blackmagic Design, EMPIRICAL LAB → Empirical Labs | 2 |
| Casse mixte | bss → BSS, dbx → DBX, spl → SPL | 3 |

### Processus de résolution (`brandHelpers.js`)
1. Texte brut → `toLowerCase()` → lookup dans le cache (Map<lowercase, {id, name}>)
2. Le cache inclut à la fois les noms canoniques et tous les alias
3. Match partiel : `resolveBrand(text)` cherche la marque dans un texte libre (ex: description d'article)
4. TTL du cache : 60 secondes → rechargement automatique après modification de la table `brands`

## 5. Détection automatique des marques

### Sur les articles fournisseurs

Le endpoint `POST /api/supplier-articles/refresh-brands` effectue :
1. Scan de tous les articles (`reference`, `designation`, `brand`)
2. Match regex dynamique basé sur les noms de marques + aliases de la table `brands`
3. Écriture de `brand_id` + `brand_canonical` sur chaque article matché
4. Application des règles `taxonomy_family_mapping` pour remplir `unified_family`

**Résultat actuel** : 3 063 / 21 944 articles (14,0%) ont un `brand_id` détecté.

### Sur les équipements

La normalisation s'applique à :
- Création (`POST /api/equipment`) : `normalizeBrand(brand)` → stocke `brand` + `brand_id`
- Mise à jour (`PUT /api/equipment/:id`) : idem
- Import CSV : idem par ligne

**Résultat actuel** : 1 798 / 2 556 équipements (70,3%) ont un `brand_id`.

### Sur les commandes

- `POST /api/orders` : résolution de marque depuis le champ `description`
- Affichage : `brand_canonical` prioritaire sur `brand` brut

## 8. Schéma de base de données

### Table `brands`
```sql
CREATE TABLE brands (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,        -- Nom canonique (ex: "L-Acoustics")
  slug TEXT NOT NULL UNIQUE,        -- Identifiant URL (ex: "lacoustics")
  website TEXT,                     -- Site officiel
  country TEXT,                     -- Code pays ISO 2 lettres
  primary_domain TEXT,              -- son | lumiere | structure | video | backline | cables
  is_active INTEGER DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Table `brand_aliases`
```sql
CREATE TABLE brand_aliases (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  brand_id INTEGER NOT NULL REFERENCES brands(id),
  alias TEXT NOT NULL UNIQUE        -- Variante de saisie (ex: "L-ACOUSTICS")
);
```

### Table `brand_family_mapping`
```sql
CREATE TABLE brand_family_mapping (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  brand_id INTEGER NOT NULL REFERENCES brands(id),
  family_id INTEGER NOT NULL REFERENCES equipment_categories(id),
  is_primary INTEGER DEFAULT 0      -- 1 = famille principale de la marque
);
```

### Colonnes ajoutées
```sql
-- equipment
ALTER TABLE equipment ADD COLUMN brand_id INTEGER REFERENCES brands(id);
ALTER TABLE equipment ADD COLUMN brand_canonical TEXT;

-- supplier_articles
ALTER TABLE supplier_articles ADD COLUMN brand_id INTEGER REFERENCES brands(id);
ALTER TABLE supplier_articles ADD COLUMN brand_canonical TEXT;
ALTER TABLE supplier_articles ADD COLUMN unified_family TEXT;
```
